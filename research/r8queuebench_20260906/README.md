# Identical-task queue benchmark

This is a performance and output-integrity benchmark only. The final24 tasks in the frozen W plan order are replayed in three fixed sequential arms: existing scheduler with4 workers, immediate-refill scheduler with4 workers, and immediate-refill scheduler with6 workers. Those tasks cover balanced stocks and foul-adjusted rebounds (real and three controls, three seeds). Their selection was fixed before timing. The other579 saved W records preload progress bookkeeping only; they are never additional training inputs.

Every replay must exactly reproduce its W configuration, raw predictions, canonical tied predictions, score, and all input/label/identity/constructor/tie audits. Each full final summary must equal W exactly. No tolerance, predictor change, checkpoint reuse, model selection, or outcome-based task selection is allowed. All data remains pre-2019. The copied model source and data files are unchanged and hashed. Server CPU preparation must replay all24 designs before GPU execution.

The new scheduler submits replacements immediately after collecting futures, before validation or persistence. Each complete output is published via an atomic no-overwrite link, fsynced, and recorded in an fsynced append log. Raw records are preserved without projection. A compact dashboard snapshot is saved at3-second intervals; full summaries run every20 seconds and at completion. Initial records are pinned by content hash and the full reference artifact is frozen. Resume revalidates completed records and hashes, recovers a published but unlogged file, and never marks a missing file completed. Conflicting outputs, changed registrations, partial/corrupt append-log tails and changed reference results fail closed; a partial log requires explicit repair. A worker exception may leave other ready results unpersisted; they remain retryable, not falsely completed.

Directory fsync follows publication and atomic replacement. Local fixtures check refill order, complete payload preservation, throttling, resume, orphan recovery and eight tamper cases, without fitting any estimator. The source agent independently reviewed the scheduler's persistence/resume design; its requested durability and initial-record pinning guards were added.

The benchmark uses one sequential timing per arm, with fresh process startup and all scheduler work included. This is a bounded practical comparison, not a repeated randomized performance trial. The old arm retains the large full-state write behavior; the new arms retain the same full output in per-task files plus the frozen initial reference. The lightweight progress.json reports actual replay counts0–72 only and is not a score candidate. A separate isolated unit limits the run to30 minutes,140 GiB and22 CPU-equivalents. The completed W directory is never edited.
