# R8t: dated biography increments with explicit input ordering and ties

This registered diagnostic has 60 tasks, each evaluated on the unchanged development folds 2012, 2013 and 2014. It has not been launched by this implementation agent. Parent-owned `research.py` and `run_sandbox.sh` handle deployment after server CPU preflight.

Four fixed backgrounds use the 41 source-only college fields: alone, plus real verified combine, plus real frozen pre-draft consensus, and plus both. Each background has five arms: no biography, the actual ten dated biography fields, and three whole-family biography shuffles. All arms run the three model seeds 0, 101 and 202. The model, label definition and calendar policy retain the source-only protocol: TabICL 32, the same fixed CPU selector, training cohorts beginning in 2007 and no later than two years before the query class, with training outcomes ending by the preceding season. All 41 base fields are retained; added eligibility uses only training coverage of at least five observations and two distinct values. Every fold retains 15 combine, four consensus and ten biography fields.

The new biography family contains contemporaneously listed age, height, weight, same-cell BMI, college class and five position indicators from archived DraftExpress mock-table player cells. It contains no actual draft position, modern NBA biography, later combine fill, report text or outcome statistic. Age reflects the displayed rounding precision and capture date; it is not exact draft-night age. Listed dimensions may have an unknown shoe convention and are distinct from measured combine dimensions. International class remains missing when unlisted. These facts describe a selective mock-prospect population and do not certify universe completeness or eliminate the separate retrospective-college-vintage limitation.

`prepare_data.py` pins every verified biography public-allowlist file and copies only approved numeric/provenance data. It preserves original biography numeric CSV tokens while joining by the previously verified player identity and cohort. The physical base input CSV has only metadata plus the 41 allowed source fields. Separate source files contain only their registered numeric families. Actual-pick metadata is used solely for the comparator and never reaches feature selection or the estimator. The original R8s consensus package is hash-identical; the extended consensus data is excluded. No 2019+ input or outcome file is read or mounted by this study.

Before selection and fitting, both training and query rows are sorted by SHA256 of the preexisting player identifier, with the identifier used only to break a hash collision. Neither this hash nor the identifier becomes a predictor. The new order can affect stochastic training, so every baseline is rerun and its scores must not be pooled with the earlier raw-order studies.

After prediction, rows whose complete selected predictor vectors are exactly identical receive the arithmetic mean of their raw predictions. NaNs compare equal and signed zeros compare equal. Distinct vectors are never rounded or merged. Raw and assigned predictions are retained per player, together with exact normalized vector hashes, duplicate memberships and both prediction hashes. All arms use this policy and are scored by Spearman with average ranks. The policy was chosen from the label-free R8order audit: its 2012 baseline contained eight identical all-missing source vectors, and only that group exhibited floating-point rank inversions under row permutations. It was not selected using outcome performance.

Biography controls move the whole ten-field row vector within draft cohort and exact missingness-pattern strata. This preserves every player's missingness and internal age/size/BMI/position relationships, unlike independent-column shuffling. The three permutation streams are reused across the four backgrounds and all model seeds. All observed biography rows are in swappable strata in these folds; actual permutations change 150–156 of 163 observed training rows for 2012, 201–207 of 215 for 2013, and 249–254 of 266 for 2014. The corresponding validation changes are 44–47 of 48, 36–41 of 41, and 45–46 of 46. Full coverage and stratum details are in `preflight.json`.

The primary summary pairs actual biography with its three matched shuffles inside each background, fold and model seed. These comparisons share selected columns, matrix dimensions and missingness masks. The no-biography arm is descriptive because its feature width differs. A family-level contrast cannot identify an individual metric's contribution, establish complementarity between backgrounds or establish significance. Three model seeds and three shuffles are not nine independent datasets. No automatic promotion, confirmation or 2019–2026 test scoring is authorized by this registration.

Local `preflight.py` passed 54 family-shuffle reorder checks, 60 design checks, 120 canonical-order roundtrips, eight duplicate-input tests, three fail-closed constructor tests and 16 tamper rejections. It independently parsed all 374 biography rows from the pinned archived sources and required the exact original feature CSV hash. Fixtures test summary arithmetic only; they are not model data or saved research results. No GPU or CPU selector was run locally. The parent server preflight must run the actual CPU selector, verify unchanged player/value sets and dated training labels, inspect all selected slot shapes, and confirm the exact constructor for every model seed before GPU tasks begin. Constructor TypeError or changed effective requested parameters fail closed; there is no fallback or weight reuse.
